# Grilling RDP

Map the consequential decisions as a design tree. Inspect the code and available context before asking the user for facts you can discover yourself. Research directly by default; delegate only when authorized and likely to save meaningful work.

Ask each currently answerable decision in a numbered round with a brief reason and recommended answer. Group related choices. Do not ask dependent questions before their prerequisite is settled. Ask as many important questions as the task needs, without making the user decide routine reversible implementation details.

Use the host question tool when available. Wait for required answers; elapsed time is not agreement. Keep optional defaults explicit. Do not repeat settled choices or request credentials in ordinary chat.

After answers, summarize scope, acceptance criteria, proof and authorized side effects. When used with half-send, obtain its execution go-ahead before implementation. Explicitly authorized skill drafting or preview preparation can proceed while product decisions remain pending. Keep separate projects and their approvals distinct.

Keep a compact decision receipt: settled choices, open decisions, access dependencies and execution authorization. When intake is done, say so clearly. A missing configuration file can block a test without reopening settled product decisions. If the owner requests skills first, finish and report their validation before starting product implementation; distinguish local readiness from publication.

Adapted from the decision-tree approach of Matt Pocock’s grilling skill: https://github.com/mattpocock/skills. This is an independently written variant, not an unmodified upstream copy.
